## 2. How the audit works

- **Fixtures = live examples (D5).** Six routes from `app/src/a11y/coverage.ts`
  (`/`, `/dashboard-01…03`, `/landing-01…02`) are mounted under the real theme
  and audited with axe-core; the coverage map is derived from the actual
  `@components` exports at test time, so a component without an audited example
  fails CI.
- **Gate.** axe defaults (WCAG 2.x A/AA + best practice); `impact ∈
  {critical, serious}` fails the suite (`BLOCKING_IMPACTS` in
  `app/src/a11y/axe-config.ts`); moderate/minor are recorded in the JSON report
  and published here.
- **Disabled rules** — environment artifacts of jsdom, not judged passes
  (table verbatim from `app/src/a11y/axe-config.ts`):

  | rule | impact | why it is off |
  | --- | --- | --- |
  | `color-contrast` | serious | jsdom has no layout engine / CSS cascade; the palette lives in CSS variables. |
  | `hidden-content` | minor | needs real layout to decide what is hidden. |
  | `css-orientation-lock` | serious | needs a real CSS engine for media queries. |

- **WAI-ARIA mapping.** `app/src/a11y/aria-patterns.ts` maps all 59 public
  components to one of 11 applicable APG patterns (or `none`/`decoration`) and
  asserts each pattern's required roles, states, and keyboard behaviour in
  `app/src/a11y/aria-patterns.test.tsx`. A pattern **passes** only when every
  check holds; a failing check is permitted only if declared as a gap written as
  a positive requirement that must *currently* fail — so fixing the component
  forces the declaration to be deleted, and a stale declaration is a hard
  failure. This is why the gap list cannot silently rot.
- **jsdom cannot assert**: computed contrast (above), real focus order / the
  dialog's Tab cycling (initial focus + Escape are asserted), and geometry
  (pointer-target size, overflow). Arrow-key roving tabindex is out of scope for
  the same reason — it is recorded as a gap in §4 rather than claimed as passing.

## 4. Known gaps (published, not implicit)

Every entry is declared in `app/src/a11y/aria-patterns.ts` with severity,
finding, and remediation, and asserted to still hold by the suite. Tally:
**6 moderate, 10 minor** across 16 entries (14 components + 1 pattern-wide note
+ 1 cross-component finding).

### 4.1 The demoting gap

| Component | Pattern | Sev | Finding | Remediation |
| --- | --- | --- | --- | --- |
| `NumberStepper` | spinbutton | moderate | The value field is a plain `input[readonly]` with no `role="spinbutton"` and no `aria-valuenow/-min/-max`; ↑/↓ are unhandled. A screen-reader user hears an empty read-only box and gets no value or bounds. | Put `role="spinbutton"` + `aria-valuenow`/`-min`/`-max` + a real label on the value input; add ↑/↓/Home/End handling. The − / + buttons stay. |

### 4.2 Moderate, non-demotion

| Component | Pattern | Finding | Remediation |
| --- | --- | --- | --- |
| `SegmentedMeter` | meter | N LED columns are bare divs — no value semantics, and no single `aria-valuenow` can be attached from outside. | Per-column `role="meter"` (or `role="img"` + sr-only summary / `role="group"` with `aria-valuetext`), synced from internal level state. |
| `BarColumnGauge` | meter | Self-driving bar + histogram with no accessible value or name at all. | Same approach as SegmentedMeter, driven from `bar`/`columns`. |
| `StepFlow` | navigation | Active step is color/blink only — no `aria-current="step"`, no text alternative for done/upcoming. | Set `aria-current="step"` on the active node. |
| `AgenticLoop` | navigation | Lit node has no `aria-current` and cycles without announcement. | Add `aria-current` + an opt-out of self-cycling for AT (static first node). |
| `SevenSegClock` | decoration | Time exists only as SVG polygons — no text node, no `role="img"`/`aria-label`; AT announces nothing (WCAG 1.1.1). | `role="img"` + `aria-label`/sr-only text carrying the time or `digits`; `aria-hidden` on the glyph SVGs. |

### 4.3 Minor

| Component / scope | Pattern | Finding | Remediation |
| --- | --- | --- | --- |
| `HealthColumns` | decoration | Carries `role="img" aria-label="System health"` (valid stopgap) but the computed lit/total summary is not exposed. | Accept a label/summary prop and set `aria-valuetext` ("18/28 NOMINAL") on the existing root. |
| `TaskCard` | progressbar | The embedded `SegmentBar` is unreachable from outside — the card announces "PROGRESS 62%" as text while the bar is silent. | Pass progress semantics onto the embedded SegmentBar. |
| `ChipRadioGroup` | radio-group | No arrow-key roving tabindex; every option is tabbable (Enter/Space work via native buttons). | Roving tabindex + `onKeyDown` arrows, or build on MUI `ToggleButtonGroup`. |
| `HazardRating` | radio-group | Same missing roving tabindex; segments are labelled by number only. | Roving tabindex + arrows; `aria-valuetext` of the hazard word per segment. |
| `Terminal` | log | No `role="log"`/live region — the typewriter transcript is invisible to AT until finished. | `role="log" aria-live="polite"` on the scroll body, or `aria-live="off"` while typing plus a one-shot summary announcement. |
| `SiteHeader` | navigation | The inner `<nav>` landmark has no accessible name. | Add an `ariaLabel` prop (defaulting to the brand name). Not reachable from an example — the nav is internal. |
| list pattern (all row components) | list | Rows are bare `<div>`s that take `role="listitem"` from the consumer; the library ships no list wrapper, so a consumer who omits it gets an unstructured run. | Optional: a `ConsoleList` wrapper (or a `list` prop on the rows) so list semantics are the default. |
| `DigitalClock` | decoration | `aria-label` sits on a generic `<div>` with no role, so AT ignores it (the digits themselves are read). | Give the root `role="timer"` (or drop the label). |
| `Marquee` | decoration | The looping track is duplicated for the seam, so AT reads every item twice; nothing is `aria-hidden`. | `aria-hidden="true"` on the duplicate track (consider pausing). |
| `Roster`, `GateRow`, `ApprovalBar`, `ChipRadioGroup`, `HazardRating`, `FilterChips`, `ConsoleNav`, `NumberStepper` | recorded finding | Native `<button>`s without explicit `type="button"` — harmless here (no `<form>`), but inside one they would submit it. | Add `type="button"` to every non-submitting `<button>` the library renders. |

## 6. Reduced-motion coverage

`prefers-reduced-motion: reduce` is verified for every animated public
component (`notes/6.3-reduced-motion.md`, `app/src/a11y/reduced-motion.test.tsx`):

- **26 / 26 animated public components** have an asserted final/static-state
  path — 25 with direct motion mechanics (found by an exhaustive inventory scan
  for `useReducedMotion`, `animation`/`transition`, `setInterval`/`setTimeout`/
  `requestAnimationFrame`) plus `TaskCard`, which composes `StepFlow`.
- The focused suite passes **15 / 15**; the full accessibility suite passes
  **38 / 38**.
- The suite asserts the shipped `MuiCssBaseline` reduced-motion guard
  (animation/transition duration `0.001ms`, one iteration) rather than
  duplicating the rule in test code.
- One production defect was found and fixed during 6.3: `HazardPrompt` inverted
  itself on a `setTimeout` regardless of the preference; it now honours
  `useReducedMotion` and settles to the final non-inverted state with no timer.

## 7. Remediation plan

Severities use axe's four-level scale (`critical` > `serious` > `moderate` >
`minor`); pattern-gap severities are declared per component in
`aria-patterns.ts`. There are no critical or serious findings anywhere in the
library today.

1. **P1 — component changes, one per gap (all planned as component changes):**
   `NumberStepper` spinbutton semantics (§4.1 — the only demoting gap), then the
   five moderate non-demotion entries in §4.2 (`aria-current` on `StepFlow`/
   `AgenticLoop`, per-column meter semantics on `SegmentedMeter`/
   `BarColumnGauge`, a text alternative on `SevenSegClock`).
2. **P2 — minor entries in §4.3:** live region on `Terminal`, `role="timer"` on
   `DigitalClock`, `aria-hidden` on the `Marquee` duplicate, `ariaLabel` on the
   `SiteHeader` nav, progress semantics inside `TaskCard`, `aria-valuetext` on
   `HealthColumns`, roving tabindex + arrows on `ChipRadioGroup`/`HazardRating`,
   and a `type="button"` sweep across the eight components listed above.
3. **P3 — app-level landmark cleanup** for the 16 moderate axe nodes in §5
   (landmark the `/landing-01` hero and section content; give duplicate
   landmarks unique accessible names).
4. **P4 — tooling upgrade:** move the audit to a real browser (the same
   `coverage.ts` map can drive a Playwright run against `vite preview`) to
   re-enable `color-contrast`, `hidden-content`, and `css-orientation-lock`, and
   to assert real focus order and arrow-key roving tabindex — the two behaviours
   jsdom cannot verify today.

Each fix is self-enforcing once landed: the matching declaration in
`aria-patterns.ts` must be deleted, and the suite fails on any declaration whose
component now passes (`a declared gap now PASSES`) — so a stale gap can never be
published after the work is done.
