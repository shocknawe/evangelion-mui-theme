# Task 3.3 — Forward `ref` to the outermost DOM node

Spec: `specs/component-api-conventions/spec.md` — "The library SHALL forward
`ref` to the outermost rendered DOM element on every component that renders a
DOM element."

## Convention chosen — React 19 ref-as-prop (no `forwardRef`)

`grep -r forwardRef components/` returned nothing: the library is 59 plain
function components, none wrapped in `styled()` or `forwardRef`. Rather than
re-wrap 59 functions, the library uses React 19's native **ref-as-prop**:

- `components/util.ts` gains a `WithRef<Tag>` helper next to 3.2's
  `RootHTMLAttributes<Tag>`:

  ```ts
  export type WithRef<Tag extends keyof HTMLElementTagNameMap = 'div'> = {
    ref?: Ref<HTMLElementTagNameMap[Tag]> | undefined;
  };
  ```

- Every props interface becomes
  `extends RootHTMLAttributes<'tag'>, WithRef<'tag'>` (or the `Omit<>` form).
- Because 3.2 already spreads the leftover props onto the root element, `ref`
  rides the **same `...rest` spread** and lands on the outermost DOM node — zero
  JSX changes anywhere. `RootHTMLAttributes` stays deliberately ref-free
  (attributes only), so a component opts into ref support by naming `WithRef`.

Why this over `forwardRef`: zero runtime wrappers (no extra component in the
tree, no DevTools noise), one-line-per-component diff, typechecks against the
same `HTMLElementTagNameMap[Tag]` parameter 3.2 already uses, and it composes
with the existing spread instead of adding a second path. Cost: components whose
root tag can vary type the ref against their primary tag (see special cases).

## Special cases

- **`GateDecisionDialog`** — renders an MUI `Modal`; `{...rest}` (and so `ref`)
  lands on the full-screen `Box` inside the portal, per 3.2's spread target and
  the task brief. The MUI-internal Modal wrapper div sits above it in the DOM;
  the ref deliberately resolves to the component-owned surface, not that
  wrapper. Verified in the probe.
- **`WikiLink`** — dual root. The ref is typed against the `<a>` case
  (`RootHTMLAttributes<'a'>`) and resolves to whichever root renders (`<button>`
  when `href` is omitted). Both verified in the probe.
- **`ZoneTitle`** — root tag follows its `component` prop (default `div`); the
  ref type follows the default.
- **Internal refs coexist, untouched**: `Terminal`/`LogConsole` keep their
  auto-scroll `bodyRef` on an *inner* element (the outer root carries the
  public ref; `{...rest}` is spread before the inner `ref=` so neither
  clobbers the other), `charts.tsx` keeps its canvas refs, `GateDecisionDialog`
  keeps its focus `approveRef` on the APPROVE button.
- **No component spreads `...rest` on more than one element** (verified: 59
  destructures + 59 JSX spreads, one each), so no component can receive a
  double-attached ref.
