# Task 3.5 — Selector specificity audit and flattening

Implements Task 3.5 of `upgrade-theme-quality-maturity` against the convention
recorded in `notes/2.3-classes-naming-decision.md`. The task does not change
tokens, variants, rendering, or component behavior.

## Result

Library-owned extension hooks are flat:

- All 59 public components emit `Nerv<Component>-root` on their outermost
  component-owned element.
- The component source has 120 distinct generated root/part hooks (123 call
  sites where a repeated part is rendered more than once).
- There are **zero CSS selectors targeting a `Nerv*` class**, therefore zero
  `Nerv*` descendant selectors, child selectors, or compounds of two `Nerv*`
  classes.
- There is no `!important` in `components/`, and no `!important` declaration is
  associated with a `Nerv*` selector anywhere in the theme.
- Addressable inner parts are styled on the element that owns their generated
  class, rather than from a `Nerv<Component>-root …` selector. Examples include
  `NervRadialGauge-track`, `NervTelemetryCard-header`,
  `NervSegmentedMeter-segment`, and `NervSiteHeader-link`.

The generated `Nerv*` classes themselves intentionally carry no CSS rule. MUI
`sx` emits a single Emotion class on the same element as the generated part
class. A consumer class can consequently use one class of specificity, without
escalating to a descendant selector or `!important`.

For the 58 components that expose `sx`, the root default `sx` fragment appears
first and the consumer `sx` fragment is appended last. `GateDecisionDialog` is
the previously documented exception that has no `sx` prop; its root and
addressable parts still expose flat `classes` hooks. `resolveClasses` preserves
the class order established in Task 3.4: generated class, `classes[part]`, then
root `className`.

Component-local selectors such as `&:hover`, `&:focus-visible`, `&::before`,
and `&[aria-pressed="true"]` are states or pseudo-elements on the same element,
not descendant overrides. Four `& b` rules format opt-in rich content supplied
inside ReactNode props; they do not select a `Nerv*` hook or cross between
library parts, so they are not customization selectors covered by this task.

## Native MUI slot migrations

The audit also found stock-MUI descendant selectors that had an equivalent
native `styleOverrides` slot. These were flattened without changing their
values or states:

| Component | Before | Native-slot form |
| --- | --- | --- |
| `MuiPagination` | root → `.MuiPagination-ul` | `styleOverrides.ul` |
| `MuiStepIcon` | root → `.MuiStepIcon-text` | `styleOverrides.text`, using `ownerState.active` for the active fill |
| `MuiChip` | root/variant → `.MuiChip-label` | `styleOverrides.label`, using `ownerState.variant` |
| `MuiAlert` | filled root → message/icon/action descendants | `styleOverrides.message` / `icon` / `action`, using `ownerState.variant` |

These entries are backed by separate styled slot elements in the installed MUI
version; their override resolvers do not re-wrap the slot rule beneath the
component root. Declaring a `styleOverrides` key alone is not sufficient proof
of flat output: ButtonGroup's `grouped` and Chip's `deleteIcon` keys are explicit
counterexamples and remain grandfathered below. No token value or timing
changed.

## Grandfathered stock-MUI structural selectors

The following selectors remain because MUI does not expose a safe native slot
that carries the required parent/sibling state. Replacing them would depend on
private DOM structure in a different way, lose state, or broaden styling to
unrelated component instances.

| Location | Selector | Reason retained |
| --- | --- | --- |
| `navigation.ts` / `MuiBreadcrumbs.li` | `& > *:last-child` | Breadcrumbs exposes the `li` slot, but not a slot for the consumer-rendered last child. |
| `navigation.ts` / `MuiStepIcon.root` | `& path` under `.Mui-completed` | The internal SVG path has no StepIcon style-override slot. |
| `buttons.ts` / `MuiButtonGroup.root` | `.MuiButtonGroup-grouped:not(:last-of-type)` | In the installed MUI version, `styles.grouped` is re-wrapped by ButtonGroup's root override resolver as `& .MuiButtonGroup-grouped`; moving the rule to that key does not flatten emitted CSS. |
| `inputs.ts` / `MuiOutlinedInput.root` | state → `.MuiOutlinedInput-notchedOutline` | MUI Core emits its own higher-specificity root-state-to-outline rules. A flat `notchedOutline` override loses to those defaults, changing hover/focus/error rendering. |
| `inputs.ts` / `MuiSwitch.switchBase` | checked `& + .MuiSwitch-track` | Track appearance depends on checked state owned by the sibling switch base. |
| `inputs.ts` / `MuiSwitch.switchBase` | focus-visible `.MuiSwitch-thumb` | Thumb appearance depends on focus-visible state owned by the switch base. |
| `inputs.ts` / `MuiSwitch.thumb` | `.Mui-checked &` | The thumb slot does not safely receive the SwitchBase's uncontrolled checked state. |
| `dataDisplay.ts` / `MuiChip.root` | `.MuiChip-deleteIcon` | Chip's root override resolver re-wraps `styles.deleteIcon` as `& .MuiChip-deleteIcon`, so that key is not genuinely flat. The independently styled `label` slot was migrated; delete-icon rules retain their original selector and scope. |
| `dataDisplay.ts` / `MuiTableHead.root` | `.MuiTableCell-head` | Moving the declarations to `MuiTableCell.head` broadens them to `variant="head"` cells outside a TableHead. The parent selector preserves the existing context and behavior. |
| `dataDisplay.ts` / `MuiListItemButton.root` | selected `.MuiListItemIcon-root` / `.MuiListItemText-primary` | The nested components do not receive the parent ListItemButton selected state. |
| `feedback.ts` / `MuiAlert.root` | filled `.MuiAlertTitle-root` | `MuiAlertTitle` is a separate component, not an Alert slot, and does not receive the parent Alert's filled state. The message/icon/action parts were migrated to native Alert slots. |

`theme/components/util.ts` also contains an unused `stampBox()` helper with an
`& > *` fragment. It has no callers and is not part of the emitted component
override map, so it cannot affect runtime specificity. It was left untouched to
avoid an unrelated API/dead-code change.

## Reduced-motion exception

`MuiCssBaseline` retains three pre-existing `!important` declarations inside
the global `prefers-reduced-motion: reduce` reset. They target `*`,
`*::before`, and `*::after`, never a `Nerv*` class, and are the accessibility
backstop that guarantees animations and transitions settle even when a
component rule is injected later. Removing them would weaken the hard
reduced-motion constraint and is outside selector-override flattening.
