# 6.1 — axe-core tooling for `app/` (CI a11y job)

Task 6.1 of `upgrade-theme-quality-maturity`. Adds an axe-core audit harness to
`app/` that runs every live-example route (Design decision **D5**: the routes in
`app/src/App.tsx` *are* the component examples) and fails on `critical`/`serious`
violations.

Result: **59 / 59 public components covered · 0 critical · 0 serious · 22
moderate finding nodes recorded** (gap list handed to Task 6.4).
`cd app && npm run test:a11y` → exit 0; `npm run typecheck` and `npm run build`
still pass. No `components/` or `theme/` source was touched.

## Tooling choice

**Vitest + jsdom + @testing-library/react + axe-core** (installed as devDeps of
`app/`; no test runner existed before).

Why jsdom rather than Playwright:

- **Determinism / CI cost.** No browser download, no server lifecycle, no
  flaky waits — the whole suite is ~3s and a plain `npm run test:a11y` in a
  Node container. The GitHub Actions job (wired in a later task) is one step.
- **The spec's gate is rule-based, not pixel-based.** The requirement is
  "rendered in at least one example and audited by axe-core". Axe's rule set
  (ARIA structure, names/roles, form labelling, landmarks) evaluates the DOM,
  which jsdom provides faithfully.
- **Task 6.2 (WAI-ARIA mapping) and 6.3 (reduced-motion) need DOM + theme
  access, not screenshots.** The harness mounts the real theme from source
  (`@theme`, `@components` aliases mirror `vite.config.ts`), so those tasks can
  assert roles/props and mock `matchMedia` in the same fixtures.

### Documented jsdom limitations

- **No layout engine / CSS cascade** → axe cannot compute geometry-dependent
  rules. `color-contrast` (serious), `hidden-content` (minor) and
  `css-orientation-lock` (serious) are **disabled explicitly** (see config
  below). Contrast is not being verified by this job — the token-level WCAG work
  belongs to Task 6.4.
- **Canvas is inert** (`getContext` returns null without the `canvas` package),
  so `LineChart`/`Waveform` mount and carry their accessible text captions but
  draw no plot. Their canvas is decorative (no `role="img"`), so no rule is
  silently skipped.
- **No focus order / pointer-target spacing / visual overflow** checks.
  Upgrade path if ever needed: the same coverage map can drive a Playwright run
  against `vite preview`; nothing about the harness assumes jsdom.

## Files

Added:

- `app/vitest.config.ts` — jsdom env, setup file, same `@theme`/`@components`
  aliases as the build so violations are attributable to the shipped source.
- `app/src/a11y/setup.ts` — jsdom shims (matchMedia, ResizeObserver,
  scrollIntoView, scrollTo) + React act environment flag.
- `app/src/a11y/axe-config.ts` — run options, disabled-rule table with reasons,
  the blocking-impact set (`critical`, `serious`).
- `app/src/a11y/coverage.ts` — `ROUTES` fixtures + component → routes coverage
  map + `NON_COMPONENT_EXPORTS`.
- `app/src/a11y/harness.tsx` — `auditRoute(path)` (mount → axe → classify),
  `classify`, `formatViolations`.
- `app/src/a11y/axe.test.tsx` — the coverage suite + per-route axe suite;
  writes `app/test-results/axe-report.json` (gitignored, CI artifact).

Changed (app only):

- `app/package.json` — `test:a11y` (CI entry) and `test:a11y:watch`.
- `app/tsconfig.app.json` — `esModuleInterop: true` (axe-core is `export =`),
  `"node"` added to `types` (report writer).
- `app/tsconfig.node.json` — include `vitest.config.ts`.
- `app/.gitignore` — `test-results/`.
- **Three app example fixes** (real findings from the first run — app markup,
  never component source):
  - `sections/FormControls.tsx` — the `TextField select` had no accessible name
    (a `role="combobox"` `div` cannot be labelled by `<label for>`), and the
    `Slider`'s hidden `input[type=range]` had no label. Fixed with
    `slotProps.htmlInput.aria-label` and `aria-label`; the three FieldLabel
    examples now pass `htmlFor`/`id` so the wrapper actually associates.
  - `sections/Navigation.tsx` — `ListItemButton` was a direct child of `List`
    (`<ul><div role="button">`), an axe `list` violation; wrapped in
    `<ListItem disablePadding>`.

## axe configuration

Defaults (WCAG 2.x A/AA + best-practice rules) with three rules disabled, each an
environment artifact rather than a judged pass — recorded verbatim in
`app/src/a11y/axe-config.ts`:

| rule | impact | reason |
| --- | --- | --- |
| `color-contrast` | serious | jsdom has no layout/CSS cascade; axe cannot resolve computed colors, and the palette lives in CSS variables. |
| `hidden-content` | minor | needs real layout to decide what is hidden. |
| `css-orientation-lock` | serious | needs a real CSS engine for media queries. |

Gate: `impact ∈ {critical, serious}` → the suite fails with rule id, help text,
node selectors and an HTML snippet. `moderate`/`minor` are logged and written to
the report without failing. Audits cover `document.body` so MUI portals
(Select menus, Dialogs) are included.

## Violations found

First run (before the app fixes): 3 blocking groups on `/` —
`label` (critical, Slider's range input), `aria-input-field-name` (serious,
unlabelled Select combobox), `list` (serious, `ListItemButton` directly in `ul`).
All three were fixed in `app/` examples (see above); none originate in
`components/` source, so no component code was edited.

Final state (repeatable, two consecutive green runs):

| Severity | Node count | Rules |
| --- | --- | --- |
| critical | 0 | — |
| serious | 0 | — |
| moderate | 22 | `region` (20 nodes: `/dashboard-02`, `/landing-01` — page content outside a landmark, including an `h1`) · `landmark-unique` (2 nodes: `/`, `/dashboard-01` — two landmarks sharing role/name) |
| minor | 0 | — |

The moderate findings sit in full-screen page chrome (`ConsoleFrame`
assemblies, hero sections), not in any single library component — exactly the
gap list Task 6.4 should publish. The machine-readable version is regenerated
on every run at `app/test-results/axe-report.json` (routes → blocking/recorded
findings + severity totals), ready to be uploaded as a CI artifact or folded
into `docs/a11y.md`.

## How later tasks extend this

- **6.2 WAI-ARIA mapping** — import `auditRoute`/`classify` from
  `app/src/a11y/harness.tsx` in additional Vitest files; to scope an audit to one
  component, either (a) add a route-shaped fixture to `coverage.ts` (the
  coverage test then demands it stay mapped), or (b) mount the component
  directly inside the same `ThemeProvider`+`CssBaseline` wrapper and run
  `axe.run` on its container — the setup file already provides the jsdom shims.
  Per-rule assertions (e.g. "GateRow exposes `role=row`/`aria-*`") can be written
  against `axe.run`'s `passes` list by dropping `resultTypes` filtering.
- **6.3 reduced-motion** — `src/a11y/setup.ts` owns the `matchMedia` shim;
  make it read a module-level flag (e.g. `setReducedMotion(true)`) exported from
  the same file so a second describe block can re-render routes under
  `prefers-reduced-motion: reduce` and assert the final-state rendering rule.
- **6.4 docs/a11y.md** — consume `test-results/axe-report.json` (already
  severity-tallied) for the published gap list; re-enable `color-contrast` there
  only if the audit moves to a real browser.
