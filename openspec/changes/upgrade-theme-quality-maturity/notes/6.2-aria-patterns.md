# 6.2 — WAI-ARIA pattern map (design.md D5)

Task 6.2 of `upgrade-theme-quality-maturity`. Maps **every public component to
its WAI-ARIA Authoring Practices pattern** and asserts the required roles,
states and keyboard behaviour in the `app/` vitest/jsdom harness built in 6.1.

Result: **11 applicable patterns · 10 pass · 1 gap (spinbutton)** — the D5 bar
(≥10/11) is met, and every other gap is recorded with a severity rather than
weakened into a pass. `cd app && npm run test:a11y` → exit 0 (23 tests, includes
6.1's axe route audits); `npm run typecheck` and `npm run build` pass. No
`components/`, `theme/` or `openspec/tasks.md` source was touched.

## Pass rule (stated so it cannot be gamed)

A pattern **passes** when every check in its set holds. A failing check is
allowed only if the failing component is **declared as a gap** in
`aria-patterns.ts`, and each declared gap is written as a *positive
requirement that must currently fail* — so fixing the component forces the
declaration to be deleted, and any regression is an undeclared hard failure.
The suite also asserts the inverse direction: a map entry marked `status:
"gap"` must be declared somewhere, so a gap can never silently disappear.

A gap counts against the pass rate only when the pattern is **not demonstrated
by any of its components** (`demotes: true`, the default). Where one component
cannot express the semantics while its siblings do (e.g. `SegmentedMeter`
inside a `meter` set that `RadialGauge`/`LedColumn`/`MeterBar` already pass),
the failure is recorded with `demotes: false` and published for 6.4 without
demoting the pattern. Only **spinbutton/NumberStepper** demotes → 10/11.

## What jsdom cannot assert (handed to 6.4 / a future Playwright run)

- **Real focus order** — the dialog's Tab-cycling inside the MUI focus trap and
  the visual focus ring. jsdom asserts *initial* focus (APPROVE) and Escape,
  which is asserted and passing.
- **Arrow-key roving tabindex** on the radiogroup / nav — the APG keyboard
  contract's ←/→/↑/↓ half. jsdom fires the events, but the components implement
  no arrow-key handling (that *is* the radio-group gap, recorded minor with
  Enter/Space working through native `<button>`s).
- **Geometry** — contrast, pointer-target size, overflow (6.1 disables
  `color-contrast` for the same reason).

## Recorded non-pattern finding

`RECORDED_FINDINGS`: several components render native `<button>`s without an
explicit `type="button"` (Roster, GateRow, ApprovalBar, ChipRadioGroup,
HazardRating, FilterChips, ConsoleNav, NumberStepper). Harmless on these
screens (no `<form>`), but inside a form the buttons would submit it. Minor;
asserted to still hold so 6.4 cannot forget it.
