## Defects / ambiguities found (reported, not fixed)

1. **DOCS_BASE regeneration trap.** `doc-site`'s `prebuild` and `predev` run
   `npm run llms` **without** `DOCS_BASE`, and `generate-llms.mjs` defaults
   `base` to `/` (`process.env.DOCS_BASE ?? '/'`), while `vite.config.ts`
   matches ("CI sets DOCS_BASE"). Any local `npm run build` / `npm run dev`
   in `doc-site/` silently rewrites `doc-site/public/llms.txt` with `/`-based
   links, dirtying the file against the pinned `/evangelion-mui-theme/`
   version. Mitigation when working in doc-site: `DOCS_BASE=/evangelion-mui-theme/`
   or `git checkout -- doc-site/public/llms.txt` afterwards. Fixing the
   default is out of scope for 7.5.
2. **StepFlow example-route gap.** `registry.json` records `exampleRoute:
   null` for `StepFlow` (58/59) and the generator warns that
   `app/src/a11y/coverage.ts` claims StepFlow renders on `/dashboard-02` but
   no `app/` page renders `<StepFlow` — COVERAGE is stale. The spec scenario
   reads "each public component appears with … example route", so this is the
   one literal miss; the registry self-documents it instead of inventing a
   route, which is the defensible behavior. Options (not taken here): render
   StepFlow on an `app/` route, or update `app/src/a11y/coverage.ts`.
3. **Rubric is not enumerated anywhere authoritative.** spec.md / proposal.md
   / design.md / docs/upgrade.md all reference "the report's rubric" and a
   4/5 target without listing the five points; the only verbatim five-signal
   list in the repo (`.context/attachments/CwFpWm/upgrade.md`) yields a
   3/5 ceiling that contradicts the ≥4/5 requirement. The rubric above is the
   documented derivation used for this scoring; the maturity scorecard's S10
   (`docs/maturity-scorecard.md` L4: "rubric score ≥4/5") inherits it.
4. `docs/upgrade.md` was **not** touched by this task (and its working-tree
   copy is untracked from other tasks' work).
